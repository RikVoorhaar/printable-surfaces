Printable Surfaces — Plan

Turn shapes (starting with the sphere) into printable rod-and-node lattices — cool geometric cages. Define the shape → generate a lattice (surface frame + interior) → thicken rods → emit STL → verify support-free with the PrusaSlicer CLI.

Phase 1 Shape definition — sphere Not started

Deliverable

  • A Surface interface (parametric now, implicit later).
  • Cube-sphere parametrization of the sphere — 6 square charts, pole-free.
  • An inside/outside test for the shape (needed later to clip interior lattices).
  • A short comparison (cube-sphere vs lat/long vs icosphere) recording why cube-sphere is the right parametrization.
  • matplotlib visualization of the parametrization.
Implementation notes
  • Cube-sphere: map each of 6 cube faces to a rectangle; normalize points on the cube to radius r. No degenerate poles, near-uniform density.
  • Each chart is a plain rectangle, so it composes with uniform grid sampling → triangles in later phases.
  • Inside/outside test for the sphere is trivial (|p| ≤ r), but expose it on the Surface interface so crystal lattices can be clipped to any shape later.
  • Visualization: matplotlib 3D line/scatter plot of chart grid lines (quick sanity check).
Phase 2 Surface-frame lattice → STL (walking skeleton) Not started

Deliverable

  • Triangulate the sphere surface from the Phase 1 parametrization; extract the 1-skeleton (edges → rods, vertices → nodes).
  • Thicken rods into cylinders (r=1.2 mm) with node joints (r=1.8 mm), unioned into one watertight mesh.
  • Emit a binary STL (~60 mm) via trimesh.
Implementation notes
  • This is the walking skeleton: proves the whole geometry pipeline end-to-end with a deliberately simple lattice (the surface frame only).
  • Rods: trimesh.creation.cylinder between two node points; joints: small spheres at nodes; boolean union into one mesh.
  • Validate with trimesh: is_watertight and is_winding_consistent before writing STL.
  • Interior lattice is not part of this phase — it arrives in Phase 4.
Phase 3 PrusaSlicer CLI setup + first slice Not started

Deliverable

  • Install/verify PrusaSlicer CLI and record its path (prusa-slicer --version).
  • A repeatable slice command that slices the Phase 2 STL with a zero-support config.
  • A pass/fail report: does PrusaSlicer generate any supports?
Implementation notes
  • PrusaSlicer is not pip-installable — install via apt, AppImage, or flatpak, and record the exact method in this phase's notes.
  • Slice with supports disabled; the goal is to see whether the geometry itself requires supports, and capture any warnings/errors.
  • Expectation to watch: the sphere surface frame may still trigger supports near the bottom cap where rods run too horizontal — that's the signal Phase 5 must fix.
  • Store generated .gcode under a git-ignored path (see .gitignore).
Phase 4 Lattice prototype & comparison Not started

Deliverable

  • Generate ≥3 lattice types for the sphere: surface frame, diamond (degree-4), honeycomb (degree-3), Voronoi, and the graphite/diamond "carbon" idea.
  • Render all side-by-side and pick the coolest (with rationale recorded).
Implementation notes
  • Diamond lattice: tetrahedral coordination (~109.5°), degree-4 — matches the "degree-4 interior" hint.
  • Honeycomb: hexagonal, 3-regular — matches the "degree-3 surface" hint.
  • Voronoi/Delaunay: organic, random-looking, harder to control.
  • Interior lattices are clipped to the shape using the Phase 1 inside/outside test.
  • Compare on aesthetics AND structural printability (rod-length distribution, overhang angles).
Phase 5 Refine chosen lattice + printability pass Not started

Deliverable

  • Refine the chosen lattice (spacing, joint geometry, minimum feature size ≥ 0.4 mm nozzle).
  • Verify no rod exceeds the configurable overhang angle; zero supports in PrusaSlicer.
  • Final STL + documented result.
Implementation notes
  • Apply the overhang rule per rod: rod direction vs +Z; flag rods flatter than the configurable angle.
  • Max bridge length is configurable (bridging is the rod analogue of overhang).
  • Iterate lattice density/orientation until PrusaSlicer reports no supports.
