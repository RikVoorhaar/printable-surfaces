Printable Surfaces — Plan

Turn shapes (starting with the sphere) into printable rod-and-node lattices — cool geometric cages. Define the shape → generate a lattice (surface frame + interior) → thicken rods → emit STL → verify support-free with the PrusaSlicer CLI.

Living document rules

This document is living. New phases are appended in the future rather than editing earlier phases. Earlier phases keep their original deliverable and status; corrections go into a new phase or a clearly-marked amendment.

Agent contract

Contract

  1. Complete whichever phases are requested by the user, in order.
  2. Commit atomically along the way — one logical change per commit, with a clear message, so every phase's artifacts are independently reviewable and revertible.
  3. After finishing (or materially changing) a phase, update this document: set the phase's status, and record implementation notes that matter for later phases (decisions, gotchas, versions, interfaces, file paths) inside that phase's collapsible notes.
  4. Do not silently rewrite history: append new phases instead of editing completed ones.

Object formA pure rod-and-node lattice (a "cage"), no skin. "Degree-3 on the surface / degree-4 in the interior" is an aesthetic hint, not a hard spec.

Phase 1 Shape definition — sphere ✓ Done

Deliverable

  • A Surface interface (parametric now, implicit later).
  • Equiangular (gnomonic) cube-sphere parametrization — 6 square charts, pole-free and near-uniform.
  • An inside/outside test for the shape (needed later to clip interior lattices).
  • A measured comparison (gnomonic vs naive cube-sphere vs lat/long vs icosphere) recording why gnomonic is right.
  • matplotlib visualization + a pytest suite locking the invariants.
Implementation notes
  • Chosen parametrization: equiangular/gnomonic cube-sphere. Map chart coordinate through tan(angle) before normalizing (tu = tan(u·π/4)). Measured triangle-area CV 0.094 (vs icosphere 0.086) — pole-free AND near-uniform. The naive "normalize raw cube coordinate" variant has CV 0.377 (~2× corner distortion) and was rejected; it's kept only in parametrizations.naive_cube_sphere_grid for the comparison. Lat/long has 128 degenerate pole triangles.
  • Bug caught & fixed: face indices into concatenated chart points used the chart count instead of the cumulative point count — produced huge spurious triangles. The "no degenerate triangles" test now guards this.
  • Package layout (new this phase): src/printable_surfaces/ with surface.py (Surface/ParametricSurface/Chart/Sphere), parametrizations.py (grids + area_stats), viz.py (matplotlib), phase1.py (runnable: uv run python -m printable_surfaces.phase1). Added hatchling build backend + pytest (dev).
  • For later phases: Surface.inside(points) is the predicate that clips interior lattices; Surface.bounding_box is available for scaling to 60 mm. Radius is stored unitless (1.0); physical mm scaling happens at STL emission (Phase 2).
  • Figures land in output/phase1/ (git-ignored).
Phase 2 Surface-frame lattice → STL (walking skeleton) ✓ Done

Deliverable

  • Triangulate the cube-sphere; extract the 1-skeleton (edges → rods, vertices → nodes).
  • Thicken rods into cylinders (r=1.2 mm) with node joints (r=1.8 mm) into one mesh.
  • Emit binary STLs (~60 mm): the printable surface-frame lattice and a thin triangulation wireframe.
  • Register both on the dashboard under lattice and triangulation.
Implementation notes
  • Walking skeleton proven end-to-end: cube-sphere (n=12, radius 30 mm) → 728 nodes, 2,178 unique edges, 174,432 triangles per STL.
  • lattice.py: merge_vertices (closes chart seams via np.unique on rounded coords), edges_from_faces (trimesh edges_unique), build_frame_mesh (cylinders + spheres, concatenated).
  • Deviation from the original deliverable: the mesh is a concatenated triangle soup, not boolean-unioned, so is_watertight=False (overlapping joints). Fine for viewing/slicing; a true watertight union is deferred to Phase 5.
  • STLs land at output/lattice/sphere_surface_frame.stl and output/triangulation/sphere_wireframe.stl; verified by reloading with both trimesh and numpy-stl (binary, finite coords).
  • For later phases: reuse build_frame_mesh for the interior lattices (Phase 4) — it only needs a node+edge frame.
  • Density sweep (follow-up): the original n=12 was too dense, so Phase 2 now emits a sweep of 5 densities (~13%, 21%, 30%, 40%, 53% of the n=12 edge count), both as printable lattices and thin triangulation wireframes. Awaiting the user's pick of density before continuing.

Phase 4 Lattice prototype & comparison Not started

Deliverable

  • Generate ≥3 lattice types for the sphere: surface frame, diamond (degree-4), honeycomb (degree-3), Voronoi, and the graphite/diamond "carbon" idea.
  • Render all side-by-side and pick the coolest (with rationale recorded).
Implementation notes
  • Diamond lattice: tetrahedral coordination (~109.5°), degree-4 — matches the "degree-4 interior" hint.
  • Honeycomb: hexagonal, 3-regular — matches the "degree-3 surface" hint.
  • Voronoi/Delaunay: organic, random-looking, harder to control.
  • Interior lattices are clipped to the shape using the Phase 1 inside/outside test.
  • Compare on aesthetics AND structural printability (rod-length distribution, overhang angles).
Phase 5 Refine chosen lattice + printability pass Not started

Deliverable

  • Refine the chosen lattice (spacing, joint geometry, minimum feature size ≥ 0.4 mm nozzle).
  • Verify no rod exceeds the configurable overhang angle; zero supports in PrusaSlicer.
  • Final STL + documented result.
Implementation notes
  • Apply the overhang rule per rod: rod direction vs +Z; flag rods flatter than the configurable angle.
  • Max bridge length is configurable (bridging is the rod analogue of overhang).
  • Iterate lattice density/orientation until PrusaSlicer reports no supports.
Future phases (append later, not yet scoped): Klein bottle, torus, apple (implicit / marching-cubes), orientation search over SO(3), bridging-length modeling, material profiles (TPU), assembly/multi-part splitting.

Implementation notes
  • URLs (Tailscale): plan → http://100.81.11.110:8000/plan/plan.html; viewer → http://100.81.11.110:8000/web/viewer.html.
  • The viewer loads any STL by root-relative path (e.g. output/phase2/sphere.stl) or via drag-and-drop; it centers, auto-fits, and reports triangle count + bounding-box size in mm.
  • Server: python3 -m http.server 8000 --bind 0.0.0.0 from the repo root, so output/ STLs are served directly. three.js 0.160.0 is vendored under web/vendor/ (no CDN/internet needed on the viewing machine).
  • Done out of sequence — needed before Phase 2 so its STL can be inspected in-browser as it is produced.
  • For later phases: emit STLs under output/<phase>/; they become viewable immediately at /output/<phase>/<name>.stl.
