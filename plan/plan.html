Printable Surfaces — Plan

Turn shapes (starting with the sphere) into printable rod-and-node lattices — cool geometric cages. Define the shape → generate a lattice (surface frame + interior) → thicken rods → emit STL → verify support-free with the PrusaSlicer CLI.

Living document rules

This document is living. New phases are appended in the future rather than editing earlier phases. Earlier phases keep their original deliverable and status; corrections go into a new phase or a clearly-marked amendment.

Agent contract

Contract

  1. Complete whichever phases are requested by the user, in order.
  2. Commit atomically along the way — one logical change per commit, with a clear message, so every phase's artifacts are independently reviewable and revertible.
  3. After finishing (or materially changing) a phase, update this document: set the phase's status, and record implementation notes that matter for later phases (decisions, gotchas, versions, interfaces, file paths) inside that phase's collapsible notes.
  4. Do not silently rewrite history: append new phases instead of editing completed ones.

Phase 1 Shape definition — sphere ✓ Done

Deliverable

  • A Surface interface (parametric now, implicit later).
  • Equiangular (gnomonic) cube-sphere parametrization — 6 square charts, pole-free and near-uniform.
  • An inside/outside test for the shape (needed later to clip interior lattices).
  • A measured comparison (gnomonic vs naive cube-sphere vs lat/long vs icosphere) recording why gnomonic is right.

Implementation notes
  • Chosen parametrization: equiangular/gnomonic cube-sphere. Map chart coordinate through tan(angle) before normalizing (tu = tan(u·π/4)). Measured triangle-area CV 0.094 (vs icosphere 0.086) — pole-free AND near-uniform. The naive "normalize raw cube coordinate" variant has CV 0.377 (~2× corner distortion) and was rejected; it's kept only in parametrizations.naive_cube_sphere_grid for the comparison. Lat/long has 128 degenerate pole triangles.
  • Bug caught & fixed: face indices into concatenated chart points used the chart count instead of the cumulative point count — produced huge spurious triangles. The "no degenerate triangles" test now guards this.
  • Package layout (new this phase): src/printable_surfaces/ with surface.py (Surface/ParametricSurface/Chart/Sphere), parametrizations.py (grids + area_stats), viz.py (matplotlib), phase1.py (runnable: uv run python -m printable_surfaces.phase1). Added hatchling build backend + pytest (dev).
  • For later phases: Surface.inside(points) is the predicate that clips interior lattices; Surface.bounding_box is available for scaling to 60 mm. Radius is stored unitless (1.0); physical mm scaling happens at STL emission (Phase 2).
  • Figures land in output/phase1/ (git-ignored).

Phase 10 Force-directed relaxed lattice ✓ Done

Deliverable

  • A force-directed layout: seed random vertices → wire with k-NN → relax with springs + repulsion + boundary conditions.
  • Surface vertices free but constrained to the sphere; interior vertices held inside by a soft wall.
  • Four variants (L=16/18/20, two seeds) with near-uniform rod lengths, all sliced.
Implementation notes
  • relax.py: Hooke springs along edges (F=(dist−L)·û), finite-range repulsion (cutoff 1.3·L), soft wall for interior at radius−L, surface projected to the sphere each step. Vertex counts derived from L so the lattice fills the ball at that spacing.
  • Two bugs found & fixed: (1) Fruchterman–Reingold's always-attractive spring pulled interior nodes onto the surface; switched to Hooke's law. (2) long-range 1/r² repulsion packed everything at the boundary (shell theorem: a uniform surface shell exerts no net force on interior nodes), so nothing confined them — switched to finite-range repulsion + an explicit soft wall.
  • Result — the original goal: interior and surface rods now match in length (e.g. L=18 → spring 20.1±3.5 vs hull 19.7±3.9), no more "short interior / long exterior".
  • Variants: 121 nodes/419 rods (L=18), 163/553 (L=16), 93/325 (L=20). All slice OK. Randomized but reproducible (fixed seeds).

Lattice generation — ideas under discussion (2026-10-20)

Phase 10's force-directed relax still isn't uniform enough on the interior. Root cause: the graph topology is fixed up front, locking interior vertices into awkward spots. Three candidate approaches (none implemented yet):

  1. Relax first, wire later — pure repulsion-only relaxation (Lloyd's / CVT) to a uniform point distribution, then wire the graph. Decouples positions from topology; gives a true energy minimum.
  2. Surface-first, grow inward — place the surface, attach one interior vertex per surface vertex (inward), connect them, add further rings as needed. Guarantees surface↔interior connectivity and degree (surface 3, interior 4).
  3. Evolutionary co-optimization — alternate position relaxation with re-wiring (reconnect nearest neighbours with random degree 3/4/5) over several rounds; topology co-evolves with positions.

Also to fix regardless of approach: rebalance vertex counts toward more interior and fewer surface (currently too many surface, too few interior).

Phase 11 Coulomb-gas lattice (Idea A + no interior/exterior split) ✓ Done

Deliverable

  • A uniform point cloud via Coulomb repulsion + a harmonic "gravity" trap (the confined Coulomb gas / jellium model) — no interior/exterior distinction, no degenerate collapse.
  • Wire the relaxed cloud with k-NN (k=3/4/5) into the lattice.
  • Five variants (120/160/200 points, k=3/4/5), all sliced.
Implementation notes
  • Per the user's refinement: drop the interior/exterior split entirely. Forces = point-charge repulsion (F ∝ 1/r²) plus a trap toward the centre (F = −k·r). This is the confined Coulomb gas, which has a provably uniform density in a ball — a genuine energy minimum, no degeneracy.
  • k_grav is set from the point count (k_grav = N/R³) so the equilibrium radius equals the target sphere radius.
  • relax.py: relax_coulomb + coulomb_lattice. Rod lengths now very uniform (std ≈ 1.2 mm vs 3.5 mm in the fixed-topology spring version).
  • Variants: 120 pts/271 rods, 160/362, 200/463, and k=3/k=5 at 160 pts. All slice OK.

Pivot: Platonic solids, optionally stretched (2026-10-21)

Spheres are the wrong shape (reachability is the hard part). New target: a Platonic solid (optionally vertically stretched into a convex polytope with the same combinatorics), per the Perplexity report docs/…/Support-Free Rod Lattices for the Platonic Solids…md.

Key theorem ("edges suffice"): if every edge is steep (≥45°) or a bridged horizontal (≤10 mm), then every face is printable and every point is reachable. So the problem reduces to a finite frame. Recipe: orient → stretch → fix solid vertices + edge subdivisions → seed + Coulomb-relax face/interior points with the frame fixed.

Report's cleanest result: cube (body-diagonal vertical) ×1.69 → rhombohedron, no bridges, 12 edges at 50°. Tetrahedron needs no stretch. Flag: single-point base needs stabilizer struts or a small flat cut.

Pivot: sliding-class relaxation method (2026-10-22)

Phase 14's ad-hoc support spring wasn't enough. Adopted the sliding-class relaxation method from the Perplexity theory report docs/sliding-class-relaxation-method.md. It replaces the hand-rolled relax + MIP with a principled pipeline, summarized in the next phase.

Core ideas: fixed node classes (V vertices / E edges / F↓ overhanging faces / F↑ upward faces / I interior) with restricted parent sets (F↓ may not use interior parents — they're out of reach); a ψ-based support energy; a hard final phase that locks in ≥2 parents; a constructive bottom-up start for faces; and an integer program with a per-rod reward β and slacks on every lower bound.

The theory reference (written to docs/sliding-class-relaxation-method.md) is itself a complete spec — sections 1–11 — and is the source of truth for the rewrite.

Phase 15 Sliding-class relaxation implementation ✓ Done

Deliverable

  • Full rewrite of printable.py to the sliding-class method: node classes + restricted parents, ψ support, anchor, hard phase, constructive start, and an MIP with β reward + slacks + clearance.
  • Result: 0 unprintable, 0 clearance violations, 0 unsupported free nodes (bottom vertex sits on the raft), mean degree ~4.7–5.3, slices OK.
Implementation notes
  • MIP (Section 7): per-rod reward β=0.6 (raises degree ~3.2 → 4.7), slacks s1/s2/sd/sf/sa on every lower bound (never infeasible), rod-rod clearance as pairwise exclusions, face bonus γ.
  • Relaxation (Sections 5–6): quadratic repulsion (r_c−d)² with κ vertical anisotropy, ψ support (sinα·L−Δz)₊²+(L−Lmax)₊²+(Lmin−L)₊² (symmetric), anchor (F↑→interior), and a hard final phase that forbids any move dropping a node below 2 parents.
  • Constructive start (Section 6.1) for faces — bottom-up, each node placed where ≥2 in-face parents exist. Applied to all faces, not just F↓.
  • Repair (Section 8): slack-driven random moves → single-pass I-node deletion → clearance-aware fallback rod. (Iterating the deletion cascaded and deleted the whole interior, so it's single-pass.)
  • Key bugs found & fixed:
    • Clearance — skip shared-node pairs. The old code counted rods sharing a node as clearance conflicts (distance 0), giving ~3,400 spurious exclusions instead of ~13 real ones. This is why Phase 14's clearance was infeasible.
    • Jitter moved fixed frame nodes off their edges (42 unprintable rods). Fixed by zeroing the step on fixed nodes.
    • Missing face inset (0.35h). Face nodes sat exactly on the edges, so their rods crossed the frame (frame-clearance 0). Adding the inset was the single biggest fix: unsupported 5–7 → 2–3 and degree 3.68 → 3.85.
    • Frame-clearance — skip shared endpoints. Face→frame rods were tested against frame rods sharing an endpoint (distance 0), so every face→frame rod was deleted. This was the real "faces not connected to the edge points" bug: fixing it took frame degree 2.3 → 5.2 and face degree 3.5 → 4.2.
    • Bridge angle-penalty. The cost term 0.3·exp(−(θ−48°)/4°) is ~48,000 for a 0° bridge, so horizontal rods were silently forbidden. Fixed to only apply to steep rods.
  • Tuning that stuck: L_MAX 22 → 28 mm (longer rods fill downhill gaps), n_face 17 → 24 → 48 (denser faces). Several repulsion knobs (power, cutoff, same-face boost, a 2-D face-spreading pass) were tried and reverted to defaults — every perturbation made the coverage worse, i.e. the relaxation is already at its equilibrium.
  • Metrics (3 seeds, rhombohedron): 0 unprintable, 0 clearance violations, mean degree ~4.7–5.3, 1 "unsupported" node that is the bottom vertex (raft-exempt). Slices clean.

Face voids — cross-slope gaps are unprintable (2026-10-24)

Remaining visual issue: elongated voids on some faces — rods on the left/right of a gap, nothing above/below. Diagnosis: the rods are steep (within ±36° of the face's downhill direction), so they form columns; the gap between columns runs perpendicular to the rods, at ~22° elevation, which is unprintable — too shallow for a steep rod (≥48°) and too steep for a horizontal bridge (≤5°).

So the face lattice is inherently columnar — this is a hard printability wall, not a wiring gap. The only lever that narrows the strips is density: max distance to the nearest rod is ~6.7 mm at n_face=24, ~5 at 48, ~4.2 at 64 (≈79% more nodes). Node coverage sits at ~9.7 mm — the organic blue-noise floor (~12% above the 8.7 mm perfect-triangular lattice; all tuning knobs made it worse, so that's the equilibrium).

Open choice for the user: keep the lighter columnar look, densify (n_face 48→64+) to narrow the strips, or accept a slightly-saggy horizontal bridge (bridge limit 10 → ~13 mm) to actually tie adjacent columns together. Not yet decided.

Phase 19 Top-face / ring posts folded into the MIP ✓ Done

Deliverable

  • Diagnosis. Horizontal-in-air support was a post-hoc “steep post to the nearest node below” pass (_add_bridge_posts). It ignored the global clearance and degree budget, the posts converged, and ~19 of 62 top-face nodes (cube) still had no parent. The method doc is explicit — “do NOT use a rod to the nearest node below post-fix” — and says to fold bridge posts into the lattice as fixed parent requirements.
  • Refactor. The set of nodes that must have a parent (post_nodes: top-face scatter nodes plus the horizontal-ring bridge intermediates) is passed into the MIP (select_rods(…, post_nodes=…)), which gives each the same ≥1/≥2 downward-rod constraints as any other non-frame node — solved jointly with clearance and degree. The relaxation anchor also pulls interior nodes under these nodes, so the parents exist where they are needed.
  • Removed _add_bridge_posts, the POST_DEG_MAX workaround and the nearest-below fallback.
  • Viewer. The STL path coloured each triangle by its normal, so a rod's cylinder facets got different colours (half-red/half-green rods). The PLY bakes one colour per rod from its elevation and is now registered next to the STL; a per-artifact download button was added too.
Outcome, and what it exposed

Icosahedron ring nodes improved from ~12 to 4 unsupported and the tetrahedron went to 0. But the flat ceiling exposed two intrinsic problems the MIP cannot fix by itself: (1) Delaunay hatching on the top face produces horizontal rods of 10–21 mm, longer than the 10 mm bridge limit; (2) a ceiling filled at ≤10 mm spacing needs ≤10 mm-spaced posts, which at a steep angle still converge — the “organic vs columns” trade-off. Both are recorded as open limitations, not implementation bugs.

Phase 20 Plate contact, solid caps, thicker rods ✓ Done

Deliverable

  • Print finding. On the printed tetrahedron the first two layers were only node cross-sections: the joint spheres (Ø1.8) reached 0.9 mm below the bottom face while the rods (Ø1.2) reached only 0.6 mm, so after the slicer drops the mesh onto the bed the rods started ~0.3 mm late.
  • Fix (after one rejected attempt). Clipping the whole frame at the face planes cut every bottom rod into a half-cylinder, so the rule became: cut only the joint caps, at face planes offset outward by half a rod diameter. Face rods are tangent to that plane and stay whole; only the joint spheres (which bulge past the rods) are trimmed. This requires joints larger than rods, so the 1.5 joint:rod ratio was restored at the new thickness.
  • Thickness. Rods Ø1.2 → Ø1.8 mm (+50 %, user request — the thin rods were hard to print in practice), joints Ø1.8 → Ø2.7 mm.
  • Solid, not hollow. The first clipper rebuilt cut parts as an unindexed triangle soup: the cut caps had hairline cracks, so the slicer saw open shells (“hollow rods”). The clipper now snaps vertices to a shared 1e-6 grid and closes each cut with an angle-ordered fan cap. The assembled frame is 629 closed bodies with every edge shared exactly twice.
  • Base. The vertex-down icosahedron gets a 2 mm flat base cut (a one-point base cannot print); the four face-down solids sit on a real face.

Phase 21 Structural post-optimization rules (exact horizontals, degree 3, upward links, angle) ✓ Done

Deliverable

  • Exact horizontals. A rod classified horizontal (|dz|/L ≤ sin 5°) must be exactly horizontal. _snap_horizontal groups near-horizontal rods into components and assigns each component one shared z (the component mean), iterated; components with a z-span > 2 mm are left alone (that would be a real slope, not a horizontal plane).
  • Minimum degree 3. Weak degree-2 points are topped up with one extra rod, deliberately allowed to break the L_MIN/L_MAX window.
  • Upward link. Every node below the top plane must have a neighbour above it; the degree cap may be broken for this.
  • Ordering bug found by verification. With the snap running last it flattened the shallow upward links just added (4 nodes on the octahedron) and destroyed the property. Final order: force degree → snap (iterated) → upward links.
  • The angle rule is absolute. The shallow fallback was rejected: a forced rod may break length and degree limits but never the 48° rule. Every forced rod must be steep (≥48°, any length) or a legal horizontal bridge (≤10 mm); if no legal candidate exists, the node is skipped rather than connected unprintably.
  • AGENTS.md added: when to delegate to subagents (bounded work that needs many tool calls or long shell runs), model routing (deepseek for implementation, GLM flash for regeneration), and the rule that a subagent must run long jobs in the foreground and may not exit until finished.

History — the twists and turns

A chronological arc of the decisions and reversals, for shaping the write-up.

  1. Sphere first. Cube-sphere parametrization, a surface frame, and interior candidates (diamond, k-NN, Coulomb). Density and scale were tuned (13/21 %, 60 → 100 mm). It looked good, but printability had not been confronted.
  2. The real wall was support. Every rod must be steep or a short bridge; the overhang/vertex-shadow theorem (K ⊆ B ⊕ C_α) turned this from a wiring problem into a geometry problem. Nearest-neighbour wiring left up to 40 % of rods unprintable.
  3. Theory doc v3. For convex polytopes, checking the edges suffices; a vertical stretch, an orientation search and a height LP give the five Platonic solids with minimal stretch. Face-down where easier, vertex-down where face-down would stretch more.
  4. The relaxation recipe. Perplexity's sliding-class method supplied the machinery: node classes V/E/F↓/F↑/I, ψ support + anchor, constructive bottom-up start, an integer program with slacks and clearance, and repair. It also warned against post-hoc “nearest node below” posts — which the first implementation did anyway.
  5. Version matrix. T1–T4 thickness × S1–S4 scale on the rhombohedron to pick a printable size; T4×S2 (Ø1.2) chosen, later revisited.
  6. Five solids. Polygon faces generalized (triangle/rhombus/pentagon); horizontal belts and rings bridged into ≤10 mm spans. Horizontal faces got explicit treatment: a base lattice on the plate, and a top face treated as a ceiling.
  7. Post-hoc posts failed → folded into the MIP (Phase 19). The ceiling was the hardest part: greedy posts converged and saturated the interior, so the parent requirement moved into the integer program and the anchor. Icosahedron rings improved; the ceiling’s long hatching rods and post convergence remained.
  8. A real print (Phase 20). The tetrahedron printed, but the first layers were node-only: joints dipped below the plate while rods did not. The first fix (clip everything) sliced rods in half and produced cracked caps that sliced hollow. The accepted fix clips only joint caps at planes offset by half a rod diameter, keeps rods as whole solid cylinders, and thickens them to Ø1.8.
  9. Structural hardening (Phase 21). Exact horizontals, minimum degree 3, an upward link for every non-top node. Verification caught the snap/upward ordering conflict, and the user then caught the deeper error: “above” is not enough — the link must lie inside the 48° cone. Forced rods now never break the angle rule.
  10. Working method. Long generations and verifications moved to subagents after several backgrounded jobs returned early; AGENTS.md now codifies when to delegate, which model to use, and that a subagent must finish its foreground work before exiting.

Still open: the ceiling gap (printable upward links / post convergence), the >10 mm top-face hatching rods, and the resulting density-versus-organic tension.
